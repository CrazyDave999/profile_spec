Validated execution paths
  Single-GPU JetSpec tree drafting, BF16 target and draft, thinking disabled.
  HF target/draft attention: SDPA. Tree attention: custom Triton paged kernel.
  Eager and compiled CUDA Graph paths both generated output on RTX 5090.
  CUDA Graph backend: triton_paged_tree_cudagraph, drafter=graphed.
  GEMM fusion is disabled because its separate verify stacks copy large weights.
  The nogather backend is not selected because it reserves much larger KV pools.
  FlashAttention 2 and a system-wide nvcc toolkit are not installed; the validated
  SDPA/Triton paths work with the PyTorch CUDA runtime and Triton's compiler.
  No changes were needed in the upstream repository's tracked files.

Small benchmark (environment validation, not a full performance evaluation)
  Official bench/jetspec/engine/tps_walltime.py, GSM8K first 4 test prompts,
  batch size 1, greedy, max 128 new tokens per prompt, depth 15, width 7,
  budget 128, graphed drafter, warm-all, reusable sessions, GEMM fusion off.
  AR: 512 tokens / 5.379 seconds = 95.2 tokens/second.
  JetSpec: 512 tokens / 2.474 seconds = 207.0 tokens/second.
  Speedup: 2.17x. Mean accepted tokens per round: 6.75.
  Log: logs/bench_gsm8k_5090.log.
  Standalone graphed smoke test peak allocation: 20.44 GiB;
  peak reserved: 21.72 GiB. This is not the benchmark's memory measurement.
  The AR baseline is JetSpecEngine.generate in the SAME JetSpec engine,
  using paged KV, compiled single-token forward and CUDA Graph replay.
  It is not SGLang, vLLM, or an external serving-engine comparison.
  torch_compile=False in the upstream log means the full HF model is not
  wrapped in torch.compile; dedicated AR/verify/draft stacks are compiled.
  Execution is offline and sequential, using direct Python engine calls;
  no HTTP server is launched. Four samples means four serial requests at
  batch size 1, not a simultaneous batch of four or a serving load test.
  The wall-clock window includes each call's tokenization, prefill, decoding
  and detokenization, while excluding model loading, dataset loading and
  warmup. These numbers are not isolated steady-state decode throughput.
  Session reuse preserves allocated KV pools and graphs, not prefix KV
  contents across requests. The benchmark does not use generate_batch.

Correctness observation
  BF16 AR/tree token equality did not pass on the smoke prompt.
  Eager execution first differs at token index 48 (zero based).
  At this first divergence, the AR top logits are '$$':35.75 and 'We':35.5;
  the tree target verification produces a tie at 35.5, and argmax selects 'We'.
  The earlier emitted token prefix is identical. This is consistent with a
  BF16 numerical difference between one-token decode and tree verification;
  it is not a proof of correctness for the engine or an fp32 validation.
  The graphed smoke prompt also differs (first mismatch index 53).
  Preserve this observation when comparing accuracy or claiming losslessness.
  Reproduce the eager diagnostic:
  source /home/qinghao/profile_spec/env.sh
  python /home/qinghao/profile_spec/diagnose_divergence.py

CPU profiling permissions
  nsys status --environment confirms Linux kernel support, but CPU perf
  sampling and scheduling collection are blocked by perf_event_paranoid=4.
  There is no passwordless sudo on this account. No system permissions or
  global sysctl settings were changed. CUDA/NVTX/OSRT collection works.
  The profiler launcher uses --sample=none --cpuctxsw=none explicitly.
  If per-process CPU perf sampling is needed later, an administrator can
  choose to run: sudo sysctl kernel.perf_event_paranoid=2
  Then check nsys status --environment and select the desired CPU options.
